## 1. 目标（Goal）

交付一个**纯前端**的贪吃蛇（Snake）小游戏，作为单页静态站点，浏览器**直接打开 `index.html` 即可运行**，无后端、无构建依赖、无网络请求。

游戏需具备完整的单局生命周期（开始 → 进行 → 暂停/继续 → 结束 → 重开），覆盖键盘与触屏两种输入，适配桌面与移动端，并对当前分数与历史最高分做本地持久化。

核心成功指标：
1. 双击/打开 `index.html` 即可游玩，无需 `npm install`、无需本地服务器、无控制台报错。
2. 桌面端键盘、移动端触屏均可完整操作方向与暂停/重开。
3. 所有验收标准（第 8 节）可被人工或脚本逐条验证通过。

## 3. 用户与使用场景（Users & Scenarios）

### 3.1 目标用户
- **桌面端用户**：使用键盘（方向键/WASD）游玩，期望快速响应、无延迟。
- **移动端用户**：使用触屏滑动游玩，期望布局自适应、操作区不被遮挡。

### 3.2 典型场景
1. **首次进入**：页面打开即显示游戏区域、当前分数 0、最高分（如有历史则显示，否则为 0），并提示"按方向键/空格开始"。
2. **单局游玩**：玩家控制蛇吃食物，分数实时增长，速度随难度/分数变化。
3. **暂停恢复**：玩家按空格暂停（游戏画面静止、提示已暂停），再按空格继续。
4. **游戏结束**：撞墙或撞自身 → 显示"游戏结束"、本局分数、最高分（若被打破则更新并提示），并提供"重新开始"入口。
5. **移动端游玩**：手指滑动控制方向，单手操作可行，按钮/分数区在视口内可见。

## 4. 功能需求详述（Functional Requirements）

### FR-1 游戏主循环（F1）
- 使用 `requestAnimationFrame` 配合时间累积（或 `setInterval`/`setTimeout`）实现按固定步长（tick）推进蛇身。
- 每个 tick：计算蛇头下一格 → 碰撞判定 → 移动/增长 → 渲染。
- 渲染目标为 Canvas（推荐）或 CSS 网格；网格为离散单元格，蛇与食物对齐到单元格。
- 页面失焦（`visibilitychange`/`blur`）时应自动暂停，避免后台空跑。

### FR-2 方向控制（F2）
- 支持键码：`ArrowUp/ArrowDown/ArrowLeft/ArrowRight` 与 `KeyW/KeyS/KeyA/KeyD`。
- 方向以"下一 tick 生效"队列方式处理，避免单 tick 内连按导致瞬时反向自杀。
- **禁止 180° 反向**：当前方向为右时，左方向输入被忽略（或缓存到下一可执行时机）；判定基准为"蛇当前实际移动方向"。
- 同一 tick 内多次输入只保留最后一个有效方向。

### FR-3 食物与得分（F3）
- 食物随机生成在**未被蛇身占据**的空单元格上；若无可放置位置（蛇填满棋盘）则视为胜利/通关（可触发结束并提示）。
- 同一时刻场上至多 1 个食物。
- 吃到食物：蛇身增长 1 节，分数 +10（基础分；若 F5 实现难度加成可调整，需在 UI 标注规则）。
- 食物不可生成在蛇身或当前蛇头下一格之外的特殊位置；生成需即时可见。

### FR-4 碰撞检测（F4）
- **撞墙**：蛇头超出棋盘边界即结束。
- **撞自身**：蛇头移动到蛇身任意已占据单元格即结束（注意：蛇尾在本 tick 内若未增长会移出，需正确处理尾随判定，避免误判）。
- 碰撞发生时立即停止主循环并进入"游戏结束"状态。

### FR-5 难度与速度（F5）
- 至少实现以下之一（推荐两者结合）：
  - **多档难度**：提供"慢/中/快"（或"简单/普通/困难"）至少 3 档，对应不同 tick 间隔（如 200ms / 140ms / 90ms）。
  - **随分数加速**：每达到一定分数（如每 +50 分）将 tick 间隔缩短一档，设最小间隔下限（如 ≥60ms）防止过快不可玩。
- 难度选择入口需在开始前可选；切换难度后立即生效（或下一局生效，需明确，推荐"开始前选择，进行中不变"）。
- 当前难度与当前速度（或档位）需在 UI 可见或可推断。

### FR-6 暂停/继续/重开（F6）
- **空格键**（`Space`）切换暂停/继续；仅在游戏进行中有效。
- 暂停时：主循环停止推进，画面冻结，UI 显示"已暂停"。
- 继续时：从暂停处恢复，不重置状态。
- **重开**：游戏结束后，按空格或点击"重新开始"按钮 → 重置分数、蛇身、方向、速度到初始状态并开始新一局。
- 重开不应清空最高分（最高分跨局保留，见 FR-7）。

### FR-7 分数与最高分（F7）
- 当前分数：每局开始为 0，吃到食物时增加，实时显示在页面上。
- 最高分：存入 `localStorage`（键名建议 `snake.highScore`），键值需做异常处理（解析失败回退为 0）。
- 每局结束时：若当前分数 > 存储最高分，则更新存储并在 UI 提示"新纪录"。
- 页面刷新后最高分仍保留并正确显示。

### FR-8 触屏支持（F8）
- 在游戏区域监听 `touchstart`/`touchend`（或 `touchmove`），根据起止点位移判定主方向（上下左右），阈值建议 ≥20px。
- 触屏方向与键盘方向遵循同一套方向逻辑（含 180° 反向禁止）。
- 触屏滑动不应触发页面滚动（需 `preventDefault` 或 CSS `touch-action`）。
- 防抖：避免单次滑动产生多次方向变更。

### FR-9 响应式布局（F9）
- 棋盘/Canvas 尺寸根据视口动态计算，保持单元格为正方形且整数像素，避免渲染糊化。
- 桌面端：棋盘居中，建议最大宽度约束（如 ≤600px），左右留白；分数与控制在棋盘上方或侧边可见。
- 移动端（≤768px 视为移动）：棋盘宽度适配屏宽（留出安全边距），分数区与重开按钮在视口内可见、不被键盘遮挡。
- 横竖屏切换时游戏状态不丢失（如进行中切屏，可保持或自动暂停，需明确，推荐"自动暂停"）。
- 不出现横向滚动条。

### FR-10 纯前端交付（F10）
- 产物为静态文件集合（至少 `index.html`，可附 `style.css`/`script.js` 或内联）。
- 不依赖任何后端、不发起任何网络请求（无 CDN 引入运行时依赖；如需字体/图标优先使用系统默认或内联）。
- 浏览器**直接打开本地 `index.html`**（`file://`）即可运行；`localStorage` 在 `file://` 下可用（需验证，若个别浏览器限制需在文档说明）。
- 不要求 Node/构建工具；若实现节点选择轻量框架，需自行保证可静态运行（如预构建产物），且不改变"直接打开即跑"的验收口径。

## 8. 验收标准（Acceptance Criteria — 可测试）

> 每条均为可独立验证的"通过/不通过"项。

### AC-1 直接打开运行（F10）
- **步骤**：在桌面 Chrome 中双击打开 `index.html`（`file://`）。
- **预期**：页面正常加载，无控制台报错；显示游戏区域、当前分数（0）、最高分；可立即开始游戏。

### AC-2 主循环与渲染（F1）
- **步骤**：开始游戏，观察蛇身是否按固定节奏持续移动。
- **预期**：蛇以稳定间隔自动移动并渲染；页面切到后台（失焦）后自动暂停，切回不继续狂跑（需手动按空格继续或已自动暂停）。

### AC-3 键盘方向控制（F2）
- **步骤**：使用方向键与 WASD 分别改变方向。
- **预期**：四向均生效；尝试 180° 反向（如向右时按左）时方向**不改变**，蛇不会因此自杀。

### AC-4 食物与得分（F3）
- **步骤**：控制蛇吃到食物。
- **预期**：蛇身增长 1 节；分数 +10；新食物立即在非蛇身空格出现；场上始终至多 1 个食物。

### AC-5 碰撞检测（F4）
- **步骤 A（撞墙）**：引导蛇头撞向棋盘边界。
- **预期 A**：游戏结束，显示结束态与本局分数。
- **步骤 B（撞自身）**：使蛇头移动到自身身体。
- **预期 B**：游戏结束；且正常尾随（蛇尾当 tick 移出后的格子）不误判为撞自身。

### AC-6 难度与速度（F5）
- **步骤**：切换不同难度开始游戏，或观察随分数增长速度变化。
- **预期**：不同难度 tick 间隔明显不同（慢/中/快可感知）；若实现自动加速，分数达阈值后速度可见提升且有下限保护（不致不可玩）。

### AC-7 暂停/继续/重开（F6）
- **步骤**：进行中按空格 → 再按空格 → 结束后重开。
- **预期**：暂停时画面冻结并提示"已暂停"；继续后从原状态恢复；结束后重开重置为初始状态且最高分不清零。

### AC-8 分数与最高分持久化（F7）
- **步骤**：打出一局有分数的结果 → 刷新页面。
- **预期**：刷新后最高分仍显示为本局结果（若为新纪录）；当前分数归 0；`localStorage` 中可查到最高分键值；键值损坏时回退为 0 不崩溃。

### AC-9 触屏控制（F8）
- **步骤**：在移动端（或浏览器移动模拟）用手指滑动上/下/左/右。
- **预期**：方向随之改变；滑动不触发页面滚动；单次滑动不产生多次方向跳变；同样禁止 180° 反向。

### AC-10 响应式布局（F9）
- **步骤**：桌面 1440 宽与移动 375 宽（及横竖屏切换）下查看。
- **预期**：棋盘自适应、单元格正方形不糊；分数与重开按钮始终在视口内可见；无横向滚动条；横竖屏切换状态不丢失（或自动暂停）。

### AC-11 可访问性基线（NFR）
- **步骤**：仅用键盘完成开始/方向/暂停/重开；检查按钮 `aria-label` 与对比度。
- **预期**：全流程可键盘操作；聚焦元素有可见焦点；关键文本对比度 ≥4.5:1。

### AC-12 无后端/无网络（F10/NFR）
- **步骤**：断网后打开 `index.html` 游玩；检查 Network 面板。
- **预期**：断网可完整游玩；无任何外部网络请求；无控制台报错。

## 9. 术语表（Glossary）

- **tick**：游戏逻辑推进的最小时间步长，每个 tick 蛇移动一格。
- **180° 反向**：与当前移动方向完全相反的方向（如右↔左、上↔下）。
- **localStorage**：浏览器本地存储，用于持久化最高分，键值在 `file://` 与 `http(s)://` 下均可用（部分浏览器对 `file://` 有隔离，需验证）。
- **Canvas / 网格**：渲染目标，离散单元格坐标系，蛇与食物对齐到单元格。
